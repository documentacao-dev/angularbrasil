# Binding não suportado em um campo de formulário

Um template faz binding, ou define como atributo estático, uma propriedade que os Signal Forms já controlam em um elemento que usa a diretiva `[formField]`.
O estado do campo é a única fonte de verdade para propriedades como `min`, `max`, `required`, `disabled` e `readonly`. Defini-las no template entra em conflito com a lógica do schema do campo.

A mensagem de erro informa o binding. Ela diz "Binding to '[min]' is not allowed..." ou "Setting the 'required' attribute is not allowed...".

```angular-ts
import {Component, signal} from '@angular/core';
import {form, FormField} from '@angular/forms/signals';

@Component({
  selector: 'app-root',
  imports: [FormField],
  template: `
    <!-- NG8022: [min] e [max] não são permitidos com [formField]. -->
    <input type="number" [formField]="f.age" [min]="18" [max]="99" />

    <!-- NG8022: o atributo required não é permitido com [formField]. -->
    <input type="text" [formField]="f.name" required />
  `,
})
export class App {
  f = form(signal({age: 20, name: ''}));
}
```

O mesmo vale para um [custom form control](guide/forms/signals/custom-controls) quando o template faz binding de um input que o campo gerencia, como `[max]` em um control que declara um input `max`.

As propriedades que não podem ser usadas com `[formField]` incluem:

- **Valores:** `value` e `checked` (gerenciadas diretamente pelo model signal subjacente)
- **Regras de validação:** `required`, `min`, `max`, `minLength`, `maxLength`, `pattern` (assim como os atributos nativos HTML `minlength` e `maxlength`)
- **Estado de interação:** `disabled`, `readonly`, `hidden`
- **Status e metadados do campo:** `name`, `dirty`, `touched`, `invalid`, `errors`, `pending`, `disabledReasons` (em custom controls, o `FormField` passa esses estados automaticamente para o control, então fazer o binding manual deles entra em conflito com a integração automática do framework)

Há algumas exceções em elementos nativos:

- `min` e `max` são permitidos em `<input>` dos tipos `date`, `time`, `month`, `week` e `datetime-local`. Nesses tipos, os limites são strings de data ou hora, como `2026-01-01`, que as regras numéricas `min()` e `max()` não conseguem expressar.
- `min` e `max` também são permitidos quando o `type` é vinculado dinamicamente, porque o compilador não consegue saber qual é o tipo do input.
- `value` é permitido em `<input type="radio">`, porque ali ele identifica a opção. O valor do campo decide qual botão de opção fica marcado.

## Depurando o erro {#debugging-the-error}

Remova o binding do template e trate a propriedade de acordo com a sua categoria:

- **Valores (`value`, `checked`):** o `[formField]` faz o binding e a sincronização bidirecional do elemento com o model signal subjacente automaticamente. Para inicializar ou alterar valores, atualize o model signal passado para `form()`.
- **Regras de validação (`required`, `min`, `max`, `maxLength` etc.):** declare-as na função de schema do `form()`, usando as [regras de validação](guide/forms/signals/validation) correspondentes.
- **Estado de interação (`disabled`, `readonly`, `hidden`):** use as regras de schema `disabled()`, `readonly()` e `hidden()`, que também aceitam uma condição `when` opcional, para que a regra dependa de outros campos. Veja [lógica de formulário](guide/forms/signals/form-logic).
- **Status e metadados do campo (`dirty`, `touched`, `errors` etc.):** não é preciso substituir nada. O `[formField]` os aplica a partir do estado do campo, e você pode lê-los no próprio campo, por exemplo `f.age().dirty()`.

Com essas mudanças, o exemplo acima fica assim:

```angular-ts
import {Component, signal} from '@angular/core';
import {disabled, form, FormField, max, maxLength, min, required} from '@angular/forms/signals';

@Component({
  selector: 'app-root',
  imports: [FormField],
  template: `
    <input type="number" [formField]="f.age" />
    <input type="text" [formField]="f.name" />
  `,
})
export class App {
  f = form(signal({age: 20, name: ''}), (p) => {
    min(p.age, 18);
    max(p.age, 99);
    required(p.name);
    maxLength(p.name, 20);
    disabled(p.name, {when: ({valueOf}) => valueOf(p.age) < 18});
  });
}
```
